## 동작 방식

### 회원가입 흐름

```
1. 사용자가 PPOP Auth에서 로그인/회원가입
   ↓
2. PPOP Auth에서 이메일 인증
   ↓
3. (선택) PPOP Auth에서 전화번호 인증
   ↓
4. PPOP Auth가 JWT 토큰 발급
   - email: "user@example.com"
   - phone_number: "+821012345678" (인증 완료 시)
   ↓
5. PPOPLINK 백엔드에서 토큰 검증
   ↓
6. 중복 검증 수행
   ├─ 이메일 중복 체크 → 중복 시 409 에러 반환
   └─ 전화번호 중복 체크 → 중복 시 409 에러 반환
   ↓
7. 검증 통과 시 신규 사용자 생성
```

### 중복 검증 로직

```python
async def _check_duplicate_email_and_phone(email, phone_number):
    # 1. 이메일 중복 체크
    if email:
        existing_user = db.query(email=email)
        if existing_user:
            raise EmailAlreadyExistsError("이미 가입된 이메일입니다")
    
    # 2. 전화번호 중복 체크 (인증된 번호만)
    if phone_number:
        existing_user = db.query(phone_number=phone_number)
        if existing_user:
            raise PhoneAlreadyExistsError("이미 가입된 전화번호입니다")
```

## PPOP Auth 연동 요구사항

### JWT 토큰 구조

PPOP Auth에서 발급하는 JWT 토큰에 다음 클레임이 포함되어야 합니다:

```json
{
  "sub": "user-uuid",                    // 필수: 사용자 ID
  "email": "user@example.com",           // 필수: 이메일
  "phone_number": "+821012345678",       // 선택: 인증된 전화번호 (E.164 형식)
  "exp": 1234567890,                     // 필수: 만료 시간
  "iat": 1234567890                      // 필수: 발급 시간
}
```

**중요**: 
- `phone_number` 클레임은 **전화번호 인증이 완료된 경우에만** 포함됩니다.
- 전화번호는 **E.164 형식** (예: +821012345678)으로 제공되어야 합니다.

## 기존 사용자 영향

### 기존 사용자는 어떻게 되나요?

- ✅ 기존 사용자는 **영향 없음**
- ✅ 기존 사용자의 `phone_number` 필드는 `NULL`로 유지
- ✅ 기존 사용자는 계속 정상적으로 로그인 가능
- ✅ 기존 사용자가 PPOP Auth에서 전화번호를 인증하면, 다음 로그인 시 자동 업데이트

## 보안 고려사항

### 1. 전화번호 인증
- ✅ PPOP Auth에서 인증된 전화번호만 저장
- ✅ 인증되지 않은 전화번호는 저장되지 않음

### 2. 개인정보 보호
- ⚠️ 전화번호는 민감한 개인정보이므로 암호화 저장 고려 필요
- ✅ 로그에 전화번호 기록 시 마스킹 처리 (예: +8210****5678)

### 3. 중복 시도 로깅
- ✅ 중복 가입 시도는 로그에 기록됨
- ✅ 보안 모니터링 가능

## 테스트 시나리오

### ✅ 테스트 완료

1. **이메일 중복 체크**
   - 새 이메일로 가입 → 성공
   - 기존 이메일로 가입 → 409 에러

2. **전화번호 중복 체크**
   - 새 전화번호로 가입 → 성공
   - 기존 전화번호로 가입 → 409 에러

3. **이메일 + 전화번호 중복 체크**
   - 둘 다 새로운 경우 → 성공
   - 이메일만 중복 → 409 에러 (이메일)
   - 전화번호만 중복 → 409 에러 (전화번호)

4. **전화번호 없이 가입**
   - 전화번호 인증 안 한 경우 → 성공 (phone_number = NULL)

5. **기존 사용자 로그인**
   - phone_number가 NULL인 기존 사용자 → 정상 로그인

### Q3: 중복 체크가 작동하지 않아요
